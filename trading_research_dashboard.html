▶ 启动研究员运行时

这个 Profile 已默认深色。启动后在 UI 里把工作区指向本仓库，再用 /research 开始盘后研究。

$ dsh --profile trading-research --no-open --port 8787
入口：/research [demo] 计算：Python · trader.cli 模型：只解释，不下单 贯穿：一个 run_id

盘后研究流水线

1
get_market_snapshot
看市场：指数、涨跌家数、data_date，并生成本次 run_id。失败即停。
2
screen_stocks
按规则 trend_volume_v1 选股：多头排列 + 涨幅适中 + 放量不极端。空候选是合法结果。
3
get_stock_research_data
把前 5 名展开成研究卡，只摆事实；估值/新闻/资金流为未接入，留空。
4
check_stock_risk
规则命中：缺数据 block 移出重点；走弱/异常/扎堆/过期只 warn。
5
generate_daily_report
落 Markdown + JSON 报告，表格数字由 Python 生成，不可改写。

职业边界 · 护栏

  • 数字只来自工具返回的 JSON
  • data_date 是工具返回值，不是“今天”
  • 空候选是合法结果，不改规则或日期重跑
  • 不输出买卖 / 目标价 / 仓位指令
  • 空字段不说成“暂无利空”
  • 不下单 / 转账 / 登录券商

本次 run 落点

运行档案data/trader.sqlite
人读副本data/processed/<date>/
研报 Markdownreports/<date>/<run_id>.md
研报 JSONreports/<date>/<run_id>.json
run_id 格式research-YYYYMMDD-HHMMSS
离线自检 · 不依赖模型

健康检查

ping_research

只做健康检查，不读行情。返回 {"ok":true,…}。

CLI 直跑快照

python -m trader.cli market-snapshot --json

断开模型也能生成 JSON——计算在 Python，不在模型。
