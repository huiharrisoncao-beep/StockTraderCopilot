Implementation Plan · Demo Edition

Stock Trader Copilot

基于 DeepSeek Harness 的 A 股智能交易研究工作流：在有限时间内，交付一个真实可运行、结果可追溯、现场可演示的 MVP。

演示日期：2026 年 10 月 26 日（星期一） 核心目标：跑通端到端工作流 不接入实盘自动下单
演示目标 架构设计 行动计划 验收标准 演示流程 立即开始

一、项目目标：先完成一个闭环

AI Trader Operating System：辅助交易员完成市场分析、量化选股、个股研究、风险评估和盘后复盘，而不是让 AI 直接替人交易。

市场环境分析→板块分析→量化选股→个股研究→风险检查→生成报告
本次演示的成功定义：通过一个入口启动工作流，获取或读取真实行情数据，完成基础指标计算和候选股筛选，再由 Harness 调用工具、让模型解释结果，最终生成 Markdown 报告和 JSON 结果。

设计原则

  • Python 负责计算：均线、收益率、成交量指标、筛选和回测。
  • Harness 负责编排：组织 Agent、工具调用和多步骤任务。
  • 大模型负责解释：总结市场信息、解释候选股筛选理由、整理研究报告。
  • 人负责最终决策：研究结果不是投资建议，也不直接触发交易。

  • 验证 AKShare 的数据接口，获取股票列表和日线数据。

  • 先让 Agent 调用 get_market_snapshot。

  • 将多步骤任务串成最小 Workflow。

验收：从 Harness 发起任务，至少成功获取市场概况、筛选候选股并解释结果。

Day 4 · 10 月 24 日（周六） — 个股研究与报告

  • 从候选股中选取少量股票开展研究。

  • 生成 Markdown 研究报告和 JSON 结果。
  • 标记数据来源、数据日期和缺失项。

验收：完整工作流能产出结构清晰、数据可追溯的研究报告。

Day 5 · 10 月 25 日（周日） — 稳定性测试与演练

  • 测试数据接口失败、数据缺失、模型失败、无候选股和报告生成失败。

2. 方案 A：用 Markdown 描述工作流，再由 Agent 执行

可以先创建 workflows/daily-stock-research.md，把流程、步骤、数据要求和失败处理写清楚。这个文件本身只是工作流说明；除非 DSH 有相应的加载机制，否则它不会因为存在于目录中就自动执行。

# A股盘后研究工作流

## 目标
分析市场环境，筛选候选股票，进行风险检查并生成报告。

## Step 1：市场分析
调用 get_market_snapshot 获取市场概况。
分析主要指数、成交额和市场涨跌情况。
数据获取失败时说明原因，不得编造数据。

## Step 2：量化选股
调用 screen_stocks。
结果应包含股票代码、名称、最新价格、20日收益率、MA20、MA60，
并记录使用的筛选条件。

## Step 3：风险检查
调用 check_stock_risk。
检查数据完整性、趋势走弱信号、异常波动和行业集中度。

## Step 4：生成报告
调用 generate_daily_report。
报告包含市场环境、选股结果、风险提示、后续观察事项、
数据来源和数据时间。

## 执行约束
- 不得编造行情数据；缺失数据必须明确标注。
- 不自动执行买入或卖出。
- 研究结果不构成收益保证。

3. 方案 B：用 Python 控制固定执行顺序

如果希望每一步都按固定顺序执行、容易测试和复现，可以用 Python 实现工作流控制器，再将入口包装成一个 DSH Plugin 工具。下面是逻辑示例，不是 DSH 原生插件接口代码。

def run_daily_research():
    # Step 1：获取市场概况
    market = get_market_snapshot()

    # Step 2：量化选股
    stocks = screen_stocks(market)

    # Step 3：风险检查
    risk_results = check_stock_risk(stocks)

    # Step 4：生成报告
    report = generate_daily_report(
        market=market,
        stocks=stocks,
        risks=risk_results,
    )

    return report

用户只需向 Agent 提出“执行今天的 A 股盘后研究”，Agent 调用类似 run_daily_research 的工具，Python 就按预定顺序执行。请为每一步补上异常处理、数据时间校验和结构化返回值。

4. 推荐方案 C：混合模式

层次建议实现方式职责
数据与量化计算Python行情处理、指标计算、选股规则、风险校验、回测
工具连接层DSH Plugin将可复用的业务能力暴露为 Harness 可调用的工具
研究编排与解释DSH Agent根据用户任务选择工具、解释结果、组织研究报告
配置与能力组合Profile / Bundle按 DSH 实际支持的机制组合和加载能力

推荐原则：让 Python 保证量化计算的确定性，让 Agent 处理需要上下文理解和语言解释的部分。不要让 LLM 自己心算关键指标，也不要把每个基础指标函数都暴露成一个工具。

5. 哪些函数适合做成 Plugin 工具？

功能建议理由
get_market_snapshot暴露为工具Agent 可以按任务需要调用
screen_stocks暴露为工具独立的量化研究能力
check_stock_risk暴露为工具或固定流程内部步骤可独立调用，也可强制纳入固定流程
generate_daily_report暴露为工具负责生成统一格式的报告
MA20、MA60、收益率计算通常作为内部函数由指标模块或选股模块调用即可
数据清洗、代码格式转换作为内部函数属于底层辅助逻辑
